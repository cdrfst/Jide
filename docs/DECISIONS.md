## D-001｜2026-10-25｜项目命名为 Jide（中文"记得"）
- **原因：** 两个字覆盖"记下来"和"你要记得"，对应记录与提醒两大核心功能；口语化，也契合"说一句它就记得"的 AI 助手形象。
- **放弃的方案：** 待办铃（Dailing）、到点（Daodian）、Duely、Noted、时序、得闲等。
- **待办：** 上线前核查应用商店重名、商标类别 9 和 42、域名与包名；避免与 TickTick/滴答清单名称、图标混淆。

## D-002｜2026-10-25｜技术栈选 Flutter + drift + riverpod
- **原因：** 团队无 Kotlin 经验；一套代码覆盖 Windows、安卓、iOS，复用率最高；drift 支持离线优先与响应式查询；插件生态与资料丰富。
- **放弃的方案：** KMP + Compose Multiplatform（无 Kotlin 经验，Windows 端基于 JVM 体积大启动慢）；Tauri 2（移动端后台能力弱，不利于提醒）；.NET MAUI、Avalonia/Uno、React Native + RN Windows、Capacitor + Electron、双原生。

## D-003｜2026-10-25｜平台顺序：Windows 桌面 → 安卓 → iOS
- **原因：** Windows 桌面端调试最快；iOS 需要 Mac 与 Apple 开发者账号（99 美元/年），放最后。
- **影响：** 平台相关代码隔离在 `lib/platform/`；提醒调度做成滚动窗口以满足 iOS 64 条上限；番茄钟用时间戳推算而非后台计时器。

## D-004｜2026-10-25｜离线优先，本地库为准，之后再做增量同步
- **原因：** 先把单机版数据模型与重复规则做扎实，再接同步，否则几乎必然重构。待办场景极少多人同改同字段，字段级最后写入为准即可，不上 CRDT。
- **影响：** 软删除；记录 `version` 与 `updated_at`；排序用分数或 LexoRank。

## D-005｜2026-10-25｜后期通过 AI 接口自然语言生成任务，本地规则解析器保留为降级方案
- **原因：** 简单输入走本地（毫秒级、离线、零成本）；复杂输入走 AI；断网或额度用完时可降级。
- **设计：** `TaskParser` 接口 + `TaskDraft` 草稿，用户确认后才入库；`ParseContext` 携带当前时间、时区、已有清单与标签；AI 用结构化输出约束格式，客户端再校验。
- **安全：** API Key 不得放客户端，经自建后端代理调用，由代理负责鉴权、限流、用量记录；任务内容发往第三方需在隐私政策说明并提供开关。

## D-006｜2026-10-25｜第一阶段（MVP）范围
- **做：** 任务与清单、子任务、标签、优先级、截止时间、RRULE 重复、本地提醒、智能清单（今天、明天、最近7天、收集箱）。
- **暂不做：** 日历、看板、四象限、番茄钟、习惯打卡、同步、协作、AI。
- **原因：** 名称与定位聚焦"任务管理 + 到期提醒"。

## D-007｜2026-10-25｜需求与变更管理倾向使用 OpenSpec，不用 GitHub Spec Kit，也不以 Cursor 替代
- **原因：** 需求会反复变更甚至推翻；OpenSpec 用增量规格（ADDED / MODIFIED / REMOVED / RENAMED）记录变更，要求写原因，并保留一份当前状态汇总规格，变更完成后归档，适合长期迭代。Spec Kit 偏从零做新功能，每个功能一份独立规格，对已有需求的演进支持较弱，流程也更重。Cursor 是编辑器，无需求生命周期管理，规则文件只是建议，不能替代。
- **状态：** 倾向，尚未安装。需先核对官方文档（安装命令、目录结构、MODIFIED 是合并还是整块替换；保险做法是修改时复制完整原需求再改），并检查 Node.js。
- **补充：** `DECISIONS.md` 与 `PROGRESS.md` 仍保留，补足 OpenSpec 不覆盖的决策原因与交接信息。
- **状态更新：** 已被 D-009 确认采用。

## D-008｜2026-10-25｜7×24 自动推进：暂不开启，条件成熟后优先 Routines，再视需要加 Ralph 循环
- **原因：** 目前没有真正不间断的 agent，各方案都靠磁盘文件接续。需先有任务清单、规格和单元测试，agent 才有客观的"做对了"标准。
- **候选：** 方案一 本地/自有服务器 Ralph 循环（`claude -p` 无头模式）；方案二 Claude Code 云端 Routines（定时或 GitHub 事件触发，以 PR 交付）；方案三 OpenHands（开源可自托管）。
- **必须的保护：** 只处理已确认需求；设迭代与费用上限；隔离运行；不自动合并主分支；测试先行；每轮收工写进度文件。
- **限制：** 云端无法编译 Flutter Windows 端，夜间只推进纯 Dart 部分，界面本机验证。

## D-009｜2026-10-26｜正式采用 OpenSpec 1.15.0，规格正文使用中文
- **原因：** 实测通过。`openspec init --tools claude` 可非交互完成；MODIFIED 为整块替换，漏写原有场景时 `validate` 与 `archive` 均拒绝执行且不改动任何文件；REMOVED、RENAMED 均可用；归档后变更目录保留在 `openspec/changes/archive/日期-变更名/`。中文标题、正文与场景通过 `--strict` 校验。
- **约定：** Requirement / Scenario 标题关键字与 SHALL / MUST、WHEN / THEN 保持英文，其余用中文；配置写在 `openspec/config.yaml`。
- **注意：** 主规格不保留被删需求的原因，原因只留在已归档变更中，所以重大推翻需同时追加到本文件。OpenSpec 不管代码清理，被改动或删除需求对应的代码与测试须在 `tasks.md` 中列出。
- **安装：** 全局 `npm install -g @fission-ai/openspec@latest`（需 Node.js 20.19.0 及以上，WSL 现为 v22.22.1）。
